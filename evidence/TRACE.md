### 1.2 Candidate order: editable before fixed

- Registration appends: fixed bindings to `fixed_bindings` ([keymap.rs:391-399](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/crates/warpui_core/src/keymap.rs#L391-L399)), editable bindings to `editable_bindings` ([keymap.rs:405-419](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/crates/warpui_core/src/keymap.rs#L405-L419)).
- `Keymap::editable_bindings()` iterates editable bindings in reverse registration order and applies any custom trigger ([keymap.rs:441-447](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/crates/warpui_core/src/keymap.rs#L441-L447); custom-trigger substitution in `EditableBinding::as_lens`, [keymap.rs:741-759](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/crates/warpui_core/src/keymap.rs#L741-L759)).
- `Keymap::bindings()` returns **all editable bindings first**, then fixed bindings in reverse order ([keymap.rs:449-464](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/crates/warpui_core/src/keymap.rs#L449-L464)). The doc comment says so directly: "Editable bindings will be returned first, followed by any fixed bindings".

### 1.3 First complete match wins

- `Matcher::push_keystroke` loops over `self.keymap.bindings()` and returns `MatchResult::Action` for the **first** binding whose `Trigger::Keystrokes` equals the pending keystrokes and whose context predicate is true ([`crates/warpui_core/src/keymap/matcher.rs:306-344`](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/crates/warpui_core/src/keymap/matcher.rs#L306-L344), the return is at [L328-330](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/crates/warpui_core/src/keymap/matcher.rs#L328-L330)).
- `AppContext::dispatch_keystroke` walks the responder chain from the focused (deepest) view outward and calls `push_keystroke` with each view's context. It dispatches the first action that a view handles ([`crates/warpui_core/src/core/app.rs:2190-2226`](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/crates/warpui_core/src/core/app.rs#L2190-L2226)).
- In the terminal input, the focused view is the `EditorView`. Its context satisfies `EditorView & !IMEOpen`, which is the predicate of both Ctrl-Y bindings. The editable `DeleteAllLeft` comes first in `bindings()`, so it is returned and the fixed `Yank` is never reached. The matcher does not report or resolve the duplicate.

### 1.4 What each action does to the text and the kill buffer

- `EditorView::handle_action` maps `Yank => self.yank(ctx)` ([mod.rs:8583](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L8583)) and `DeleteAllLeft => { self.delete_all(CutDirection::Left, false /* cut */, ctx); ctx.emit(Event::DeleteAllLeft); }` ([mod.rs:8595-8598](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L8595-L8598)).
- `yank` inserts `self.internal_clipboard` at the cursor ([mod.rs:4301-4314](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L4301-L4314)). The field is declared at [mod.rs:1784](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L1784) and starts empty ([mod.rs:3201](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L3201)).
- The internal buffer is filled only by `EditorModelEvent::ShellCut` ([mod.rs:7642-7645](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L7642-L7645)). The default kill commands produce that event through `editor_model.shell_cut`:
  - Ctrl-U → `editor_view:clear_and_copy_lines` ([mod.rs:582-588](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L582-L588)) → `clear_and_copy_lines` ([mod.rs:6300-6310](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L6300-L6310)).
  - Ctrl-K → `editor_view:cut_all_right` ([mod.rs:808-814](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L808-L814)) → `delete_all(Right, true)`, cut branch ([mod.rs:6242-6258](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L6242-L6258)).
  - Ctrl-W → `editor_view:cut_word_left` ([mod.rs:766-772](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L766-L772)) → `cut_word_left` ([mod.rs:4669-4682](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L4669-L4682)).
- `DeleteAllLeft` calls `delete_all` with `cut = false`, which takes the plain `buffer_edit` branch ([mod.rs:6259-6294](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L6259-L6294)). It deletes from the line start to the cursor and does not touch `internal_clipboard`. The terminal input also reacts to `Event::DeleteAllLeft`: when AI input is enabled it switches input back to shell mode ([`app/src/terminal/input.rs:11574-11585`](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/terminal/input.rs#L11574-L11585)).

**Why Ctrl-Y deletes on Linux/Windows:** both bindings match the same key and context, the keymap lists editable bindings before fixed ones, and the matcher stops at the first match. So Ctrl-Y always runs Delete All Left. Delete All Left does not write the kill buffer, so a killed sentinel is never restored. On macOS the editable binding is Cmd-Backspace, so nothing shadows fixed Ctrl-Y (source reading only, see section 3).

- Automated (synthetic test-user fixture, production key dispatch): `m1-regression/red-run-committed.log`. Ctrl-U emptied the input. Ctrl-Y then failed the final assertion with `Expected "echo ctrl-y-yank-sentinel"` / `Actual: ""` (nextest: 0 passed, 1 failed, 338 skipped, exit 100).

Ctrl-Y after Ctrl-U, Ctrl-K or Ctrl-W never restored the killed text. After Ctrl-W left `first `, Ctrl-Y also deleted that remainder, which is Delete All Left behavior.

### 3.2 Bounded inventory of other fixed/editable overlaps

**Boundary inspected:** every `FixedBinding` and `EditableBinding` registered in `app/src/editor/view/mod.rs::init` ([L186-992](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/editor/view/mod.rs#L186-L992)), evaluated for Linux/Windows. This means: `with_key_binding` and `with_linux_or_windows_key_binding` triggers, `new_per_platform` `linux_and_windows` strings, `cmdorctrl` → `ctrl`, and custom-action triggers converted to keystrokes on non-macOS ([`app/src/lib.rs:1320-1323`](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/lib.rs#L1320-L1323) using `custom_tag_to_keystroke`, [bindings.rs:265-349](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/app/src/util/bindings.rs#L265-L349)). A pair counts when the normalized keystroke is equal and both context predicates can hold together. `alt` and `meta` are separate `Keystroke` fields ([keymap.rs:320-328](https://github.com/warpdotdev/warp-stanford/blob/f411fbc20e6283a2abcdd1ed64bf5b67df864f82/crates/warpui_core/src/keymap.rs#L320-L328)), so `meta-d` and `alt-d` are not the same key. Method: a small script compared all 54 fixed and 42 Linux/Windows-defaulted editable registrations in that range, and each hit was checked by hand. Bindings outside this function (terminal `Input`, workspace, code and notebook editors) were not inventoried.

The other five overlaps run the same action, so the user-visible effect is unchanged. There is one side effect: if a user rebinds or clears those editable rows, the fixed binding keeps the old key working. That is outside this mission and is not being fixed.
